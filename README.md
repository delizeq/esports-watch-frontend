
# Esports Watch — Frontend

Esports Watch — вебсайт для перегляду кіберспортивних матчів, турнірів та команд.

Фронтенд написаний на HTML, CSS та JavaScript і працює з Django REST API.

## Можливості

- Перегляд списку кіберспортивних матчів.
- Фільтрація матчів за датою.
- Перегляд команд, турнірів та статусів матчів.
- Реєстрація нових користувачів.
- Авторизація через JWT (access та refresh токени).
- Автоматичне оновлення access-токена.
- Перегляд захищеної сторінки профілю.
- Вихід з акаунта.
- Перенаправлення неавторизованих користувачів на сторінку входу.
- Повернення користувача на захищену сторінку після входу.

## Сторінки

- `index.html` — головна публічна сторінка зі списком матчів.
- `register.html` — сторінка реєстрації.
- `login.html` — сторінка входу.
- `profile.html` — захищена сторінка з інформацією про користувача.

## Запуск проєкту

### 1. Запуск Backend

Відкрий термінал у папці Django-проєкту.

Встанови залежності:

```bash
pip install -r requirements.txt
```

Виконай міграції:

```bash
python manage.py migrate
```

Запусти сервер:

```bash
python manage.py runserver
```

Backend працюватиме за адресою:

`http://127.0.0.1:8000/`

### 2. Запуск Frontend

Відкрий окремий термінал у папці `esports-watch-frontend`.

Запусти локальний сервер:

```bash
python -m http.server 5500
```

Або скористайся розширенням Live Server у VS Code з портом 5500.

Відкрий сайт:

`http://127.0.0.1:5500/index.html`

## Авторизація

Для авторизації використовується JWT.

Після успішного входу сервер повертає два токени:

- `access` — використовується для доступу до захищених API.
- `refresh` — використовується для отримання нового access-токена.

Токени зберігаються у `localStorage` браузера.

Для захищених запитів використовується заголовок:

`Authorization: Bearer <access_token>`

Якщо access-токен закінчився, фронтенд намагається автоматично оновити його через refresh-токен.

При виході обидва токени видаляються з `localStorage`.

## Перенаправлення користувачів

Якщо неавторизований користувач відкриває `profile.html`, його перенаправляє на:

`login.html?next=profile.html`

Після успішного входу користувач повертається на сторінку профілю.

Якщо авторизований користувач відкриває сторінку входу, його автоматично перенаправляє на іншу сторінку сайту.

На головній сторінці неавторизований користувач бачить кнопки входу та реєстрації, а авторизований — своє ім'я та кнопку виходу.

## API

Frontend використовує такі ендпоінти:

| Метод | Ендпоінт | Призначення |
|---|---|---|
| GET | `/matches/` | Отримання матчів |
| GET | `/teams/` | Отримання команд |
| GET | `/tournaments/` | Отримання турнірів |
| GET | `/games/` | Отримання ігор |
| POST | `/auth/register/` | Реєстрація |
| POST | `/auth/login/` | Вхід та отримання JWT |
| POST | `/auth/token/refresh/` | Оновлення access-токена |
| GET | `/auth/me/` | Отримання даних авторизованого користувача |

Публічні GET-запити доступні без авторизації.

Для захищених запитів необхідний JWT access-токен.
